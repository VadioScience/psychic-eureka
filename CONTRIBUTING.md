# 🤝 Руководство контрибьютора

Спасибо что хотите помочь с BlockLiftGun Mod! Это руководство поможет вам начать.

## 🚀 Как начать

### 1. Форкните репозиторий
```bash
# Нажмите Fork на GitHub
```

### 2. Клонируйте ваш fork
```bash
git clone https://github.com/ВАШ_НИК/BlockLiftGun.git
cd BlockLiftGun
```

### 3. Добавьте upstream
```bash
git remote add upstream https://github.com/ОРИГИНАЛЬНЫЙ_НИК/BlockLiftGun.git
```

### 4. Создайте branch
```bash
git checkout -b feature/моя-фишка
# или
git checkout -b fix/исправление-бага
```

## 📝 Правила кода

### Java Style Guide

```java
// ✅ Правильно
private static final int MAX_POWER = 100;

public void doSomething() {
    if (value > 10) {
        performAction();
    }
}

// ❌ Неправильно
private static final int mMaxPower = 100;

public void doSomething(){
    if(value>10){performAction();}
}
```

### Комментарии
```java
// Одна строка - для простых объяснений

/**
 * Несколько строк - для методов и классов
 * @param param описание параметра
 * @return описание возврата
 */
```

### Именование
- Переменные: `camelCase` (myVariable)
- Константы: `UPPER_SNAKE_CASE` (MY_CONSTANT)
- Методы: `camelCase` (myMethod())
- Классы: `PascalCase` (MyClass)

## 📝 Commit Messages

### Формат
```
[TYPE] Краткое описание что изменилось

Более подробное объяснение если нужно.
Может быть несколько строк.

Closes #123
```

### Типы:
- `[FEATURE]` - новая функция
- `[FIX]` - исправление бага
- `[DOCS]` - обновление документации
- `[REFACTOR]` - рефакторинг кода
- `[TEST]` - добавление тестов
- `[CHORE]` - обслуживание проекта

### Примеры:
```
[FEATURE] Добавлена поддержка режимов стрельбы

[FIX] Исправлена ошибка с зависанием блоков

[DOCS] Обновлено описание BlockLiftGunItem

[REFACTOR] Рефакторинг системы частиц
```

## 📋 Pull Request Process

### 1. Обновите от upstream
```bash
git fetch upstream
git rebase upstream/main
```

### 2. Запушьте в свой fork
```bash
git push origin feature/моя-фишка
```

### 3. Создайте Pull Request на GitHub
- Заполните шаблон PR
- Опишите что изменилось
- Ссылаетесь на issue если есть
- Выберите reviewers

### 4. Ответьте на комментарии
- Внесите исправления если нужны
- Пушьте изменения в тот же branch
- PR автоматически обновится

### 5. Merge
После одобрения reviewer ваш PR будет merged!

## 📚 Типы контрибьюций

### 🐛 Исправление ошибок
1. Создайте Issue с описанием
2. Создайте branch: `fix/название-бага`
3. Исправьте ошибку
4. Создайте PR с ссылкой на Issue

### ✨ Новые функции
1. Обсудите сначала в Issue (или создайте)
2. Создайте branch: `feature/название-функции`
3. Реализуйте функцию
4. Добавьте документацию
5. Создайте PR

### 📖 Документация
1. Создайте branch: `docs/что-обновляется`
2. Отредактируйте Markdown файлы
3. Проверьте что читается хорошо
4. Создайте PR

### 🔧 Улучшение кода
1. Создайте branch: `refactor/что-улучшается`
2. Рефакторьте код
3. Убедитесь что всё работает: `./gradlew build`
4. Создайте PR с объяснением

## 🚫 Что НЕ делать

- ❌ Не менять версию в mods.toml без обсуждения
- ❌ Не менять основной функционал без approval
- ❌ Не добавлять большие dependency без обсуждения
- ❌ Не удалять документацию
- ❌ Не коммитить IDE файлы (.idea, .vscode)
- ❌ Не форматировать весь файл если меняется только одна функция

## 📊 Код Review

### Что мы смотрим:
- ✅ Работает ли функция как описано
- ✅ Соответствует ли стилю проекта
- ✅ Нет ли регрессий
- ✅ Есть ли комментарии к сложному коду
- ✅ Обновлена ли документация

### Как получить одобрение:
1. Убедитесь что код скомпилируется: `./gradlew build`
2. Протестируйте в игре: `./gradlew runClient`
3. Напишите хорошее описание PR
4. Будьте готовы ответить на вопросы
